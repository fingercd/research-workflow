# 任务卡、研究顾问交接与结果反馈

按当前项目已有格式记录即可。本文件提供需要时可采用的模板，不要求每个小实验都生成多个新文档。

## 简短任务卡

```markdown
# 本周期研究任务

- 研究目标与当前主线：
- baseline：组成、可比条件、已验证结果及对应版本。
- 待改进模块：来源、预期作用、当前版本、最好版本、依赖关系。
- 本轮问题：上一轮什么证据支持这次改动？
- 主要改动与保持条件：
- 验收：主指标、比较符号、正常评测口径。
- 阶段条件：早期淘汰线、作用窗口、阶段复审点、转组合条件。
- 预算：小实验次数或时间、正式训练长度、任务数及 GPU 边界。
- 授权与位置：执行范围、服务器/本地分工、是否允许外部提交和定时跟进。
-研究顾问：当前研究对话、上一份完整回复、已提交材料与待回结果。
- 已否定候选与原因：
- 当前下一步及其触发条件：
```

用户已经在上下文说清的内容直接填入。缺少某种阶段条件时写“不适用”或“尚未约定”，不要从其他项目复制阈值。

## 给研究顾问的证据包

先列文件目录和一页阅读说明，再放足以复核判断的材料。材料宁可充分；避免只有结论截图而没有配置和原始数值，也避免把整个无关工作区无说明地塞入。

- **问题和主线**：原始 idea 来源、用户核心疑问、baseline 组成、当前实现与原始方案的差异、硬约束和本周期要回答的问题。
- **实际代码与改动**：产生结果的冻结代码、相关调用路径、配置与运行命令、commit/tag、未提交差异；不要仅提供后来修改的工作副本冒充训练源码。
- **实验结果**：当前周期与必要历史周期的逐轮主指标、同轮伴随指标、loss、完整曲线、训练预算、最好及最新进度、权重选点信息。
- **机制诊断与负向反馈**：固定权重干预、更新或作用路径诊断、正常结果与干预结果的区分、被否定而未正式训练的候选。
- **可追溯信息**：seed、数据/权重版本、环境、有效日志、工程失败记录、实验追踪系统链接与云端核验状态。
- **前序判断**：上一份完整研究顾问规划、已实施与未实施建议及原因，哪些假说重复失败，哪些正向版本要保留。

必要源码和结果尽量完整，原始数据、大权重只在确有必要且本次授权覆盖时附带。排除认证凭据、令牌、认证日志与无关个人信息。核对包内文件、运行版本和结果是否对应；不要因发送失败重复创建不同的科学版本。

##研究顾问提问模板

```text
请继续在这个对话中指导我们的科研迭代。你的角色是根据实测材料提出原因假说、下一步实验与判别条件；执行智能体负责在授权范围内实施，并把反馈继续交回这里。

当前任务、baseline、创新主线与用户验收：
【填入任务卡中的必要信息】

本周期实际做了什么：
【按顺序列小实验、主要改动和正式训练，说明哪些只是计划】

本周期结果与仍然不确定之处：
【正常主指标及同轮伴随指标、同条件基线和上一版差值、完整曲线、机制诊断、负向反馈；指出未覆盖的作用窗口和协议差异】

需要你优先回答：
1. 哪些结论已经得到证据支持？哪些只是假说？当前问题更可能在实现、学习机会、信息作用路径，还是研究假设？
2. 下一轮最值得做的少量小实验是什么？逐项说明假说、保持条件、主要变量、观察量和不同结果分别怎样决定下一步。
3. 小实验支持后，哪一个改动最值得投入一次正式训练？应覆盖什么时间窗口，如何与现有 baseline 和最好版本比较？
4. 哪些结果应继续、撤回当前改法或停止固定配方？如果同一方向反复无效，应该改变什么更大的假设，而不是继续微调同一系数？
5. 哪个已有有效版本应保留？是否达到转组合或整体结束的条件？

请结合附件中的实际代码和结果，不用“再试试”代替具体实验。不要擅改数据、输入条件、基础配方、评分、目标或资源预算；需要改变时，先说明原因及可比性影响。建议按信息价值与成本排序，不为凑实验次数铺开大量变体。

请输出完整 Markdown 分析，标明证据来源、未知项、下一步顺序和停止条件；若本次用户要求直接聊天解释，则以该形式完整回答。
```

## 取回意见后怎样处理

阅读全文，保留原始回复，确认它针对本次包和当前周期。用简短说明列出采纳的建议、暂不采纳的建议及其依据，把建议变成实际可执行的诊断或改动。研究顾问未给足判别方法时，在同一对话补充证据并追问，不把模糊规划交给训练队列。

当用户已授权直接交接与持续迭代，执行完整循环，不让用户反复承担搬运材料的工作。当前授权不覆盖发送时，先准备包与 prompt，明确待提交对象；历史交接授权不能代替本次任务的发送授权。调用浏览器或外部服务时再遵循该工具适用的指南，不把某个浏览器实现写成科研方法本身。

## 每轮结果表

| 周期/小实验或正式训练 | 改了什么 | 为什么改 | 实测效果与对照 | 结论与下一步 |
|---|---|---|---|---|
| 使用明确模块名与版本 | 主要功能或训练改动 | 上一轮证据/待检验假说 | 正常结果、差值、预算与作用窗口 | 保留、否定、继续诊断、训练或转向 |

主表以用户指定的最好轮或区间最好轮为准，其他指标同轮取值；需要末轮时另列，不分别拼接多个指标的最好值。

周期复盘首先报告：实际完成多少次小实验、多少个正式训练、哪些方案被否定、哪些版本被保留，以及当前离目标多远。研究顾问交流次数、等候时间、恢复训练和工程启动失败不冒充正式研究轮次。

附用户需要的最新曲线：baseline 与候选颜色稳定，标注横轴训练轮次、主指标含义、作用窗口和完成进度，保留下降段；无数据的组标未启动或失败。重点解释为什么还未达标及下一步能解决什么不确定性。只有用户要求详细机理时再展开梯度、优化器或模块公式。
