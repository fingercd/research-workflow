# 科研实验迭代工作流

以实测证据驱动研究：明确问题与 baseline → 小实验诊断 → 选择改动 → 正式验证 → 保留、复审或转向。

## 分工与范围

- **研究负责人**确定研究目标、验收口径、预算和资源边界。
- **执行智能体**理解原始方案、核对实现、执行授权实验、解释反馈并维护记录。
- **研究顾问**结合代码与实验材料，提出原因假说、下一步实验、判别方法和方向取舍。可由 ChatGPT Pro 或其他模型承担；角色不绑定服务商，建议不能替代实测证据。

先判断本次请求是说明方案、只读诊断、一次实验还是持续迭代。已有授权范围内的常规工作自主完成；只读、暂停与预算限制按当前请求执行。技能不授予外部发送、开启训练、停止其他任务、定时跟进或公开发布的额外权限。用户明确要求建立持续目标时，才使用宿主支持的目标管理能力。

## 接入项目

按需阅读项目说明、当前计划、原始研究材料和已有实验记录，复用现有文档格式。先明确：

| 内容 | 决策用途 |
|---|---|
| 研究问题、主指标与验收条件 | 明确何时达标，避免随结果改变目标 |
| baseline 的组成、版本与完整记录 | 说明对照依赖的输入、监督、初始化和评分 |
| 候选模块的来源、实现与依赖 | 区分原始方案、适配、辅助调参和组合配置 |
| 本轮主要变量与保持条件 | 让实验能回答一个明确问题 |
| 模块生效时间与效果判断窗口 | 区分早期淘汰、阶段检查与最终效果 |
| 小实验与正式实验预算、并发及资源 | 控制投入，资源编号由当前项目决定 |
| 最好版本、已否定候选和顾问上下文 | 保留有效积累，避免重复试错 |

已有上下文能确定的直接沿用；未知项明确记录，只在实际影响执行时澄清。需要组织输入与反馈时读取 [交接模板](references/model-handoff.md)。

## 一轮迭代

1. **提出待验证问题。** 说明上一轮证据、原因假说、主要改动与预期观察。一次正式比较尽量只改变一个有依据的主要因素。用户要求完整复现或指定组合时，按范围实现，列清变化，不改成其他课题。
2. **先做少量有证据的小实验。** 可从约三到四次诊断与改进开始，再投入一次必要正式实验；次数服从实际信息价值和预算。证据充分时提前正式验证，候选被否定时提前复审，不机械凑数。聊天、等待、重复验收和工程重启不算研究迭代。
3. **筛选后冻结候选并正式验证。** 每个方向优先选择一个值得投入的版本。检查直接影响实验真实性的问题，随后运行覆盖作用窗口的预算，避免无限预检。已验证且条件一致的 baseline 直接复用；比较条件改变时说明旧基线的适用边界。
4. **判断正常任务收益。** 按项目约定选择 checkpoint 或判断区间，伴随指标取同轮同评测条件的值。比较匹配 baseline、上一最好版本及必要控制，保留完整曲线和对应权重。区分实现正确、作用得到支持、任务收益得到支持与验收达标。
5. **正向反馈保留版本，负向反馈交回复审。** 有价值提升但未达标时，在预算内继续有依据的改进；小幅单次改善只记为信号。正式结果不理想或连续诊断缺乏支持时，把完整证据交回已有研究顾问上下文，要求明确下一步实验及去留条件。

## 继续、停止与转向

- **过程活跃不等于方法有效。** 梯度非零、参数更新、loss 下降和输出变化只是过程证据。重点检查模型是否利用预期信息，以及这种利用是否帮助正常任务。诊断设计见 [实验决策](references/experiment-decisions.md)。
- **早期底线与效果窗口分开。** 保留项目明确的硬早停条件；通过底线不等于成功。模块尚未生效或尚未到作用窗口时，不仅凭早期未赢 baseline 宣布方法无效。若 baseline 早期见顶、模块较晚充分学习，检查训练预算、学习率和接入时机。
- **停止的含义明确。** 区分阶段结束等待复审、终止固定配方、负责人要求暂停和整体目标完成；前三者不自动等于方法无效或研究完成。
- **反复失败先定位，再扩大调整。** 用能区分原因的小实验定位实现、优化、信息路径或研究假设的问题。路径正确却反复没有任务收益时，调整作用位置、表达、监督来源或模块交互，避免只微调同一失败假设的系数。替换研究主线或扩展预算时交由负责人决定。
- **各分支分别处理。** 保留已有最好且有证据的版本，改变持续无效的分支，不连带推翻有效积累。
- **按阶段目标收敛。** 项目规定任一单模块达标后转组合时，停止新开单模块训练，固定成功设计，以组合实验改进另一模块。整体达标后完成必要核验与归档，不自动扩展更多模块或实验。

## 顾问反馈循环

复用已有研究对话或会话，提供产生结果的实际代码、差异、配置、完整指标与曲线、机制诊断、负向证据、已否定方案和当前约束。材料足以复核判断；排除凭据与无关隐私。需要交接时使用 [模板](references/model-handoff.md)。

本次已授权直接提交时自主发送并取回完整回复，不每周期重复确认；未覆盖发送时先准备可审阅材料。阅读全文，核对建议与事实、目标及预算，再转成具体实验。顾问与负责人要求冲突时指出冲突并遵从当前任务要求。

等待期间推进独立整理或准备，避免重复提交。定时检查仅在被请求时建立，并复用现有安排。检查与汇报频率分别设置，无新信息不刷屏。等待、接口故障与工程启动失败不能作为方向被否定的科学证据。

## 实验记录与汇报

采用项目指定的记录系统；可使用 SwanLab、其他实验追踪服务或结构化本地记录，不固定依赖某个账号或工具。项目要求云端记录时，所有训练、评测与小实验均上传并回读核验；失败保留本地日志并补传。

记录配置、seed、代码版本与未提交差异、数据及权重版本、命令、环境和日志。重要实验固定源码快照或版本 tag，确保结果与代码对应。修改前检查版本控制状态并保全已有改动。实验与图表名称应直观表达主要变量及指标含义。

汇报先给结论，然后回答：**做了多少次有效迭代 → 改了什么 → 为什么改 → 实测效果 → 未达标的原因与未知项 → 下一步。** 区分小实验、正式训练和计划，附必要的 baseline 与候选完整曲线，保留下降段并标记作用窗口。使用完整模块名和清楚的轮次编号；实现细节与机理按问题需要展开。
